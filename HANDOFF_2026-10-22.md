# Раздача VPN/Proxy и IPv6 — передача работы 22.10.2026

## Запрос и состояние

Пользователь раздаёт мобильный интернет с Android на Mac, использует WireGuard. Попросил улучшить скорость и стабильность VPN/Proxy-раздачи и сохранить работы/замечания в проекте для следующего агента. Ранее отдельно попросил изменить IPv6: блокировать его только у получающих интернет устройств, поскольку глобальное отключение мешало AdGuard.

Готовится выпуск **3.14 / 69**, обе release-сборки. Изменения сделаны в текущем рабочем дереве, без коммита и без установки на телефон. Это дерево уже содержало множество изменённых/неотслеживаемых файлов до работы над раздачей; их нельзя считать целиком изменениями текущей задачи. Репозиторий существует, замечание об отсутствии Git в старом handoff за сентябрь устарело.

## Что реализовано

1. **Повторное использование исправного маршрута.** `TetherRoute`, `TetherLease`, `TetherScripts`: хеш конфигурации и результат сохраняются отдельно в `tether_route_state`. Хеш включает версию/APK, boot id, поколения интерфейсов, режим, VPN netId и параметры прокси, включая учётные данные. Пароли в записи хеша не сохраняются. Новый процесс приложения может принять прежний маршрут, только если совпала конфигурация и прошла проверка реальных правил, интерфейса, маршрутов, HEV и SOCKS. Повторное событие не убивает исправные процессы.
2. **Защита при перестроении и контроль ошибок.** Перед удалением старого маршрута устанавливаются отдельные `NMS_HOLD`/`NMS_HOLD6`. Они переживают teardown. Проверяются DNS, обе policy rules, недоступность прямого выхода, разрешённые направления, NAT/MSS обычного VPN и порядок защитных/DNS-правил. После проверки маршрут освобождается от временной блокировки; при ошибке защита устанавливается снова. Дубликаты временных переходов удаляются с конца, сохраняя первый действующий переход. Мутация заканчивается в `NonCancellable`, даже если закрыт экран, который её начал.
3. **UDP без копирования полезной нагрузки.** `SocksUdp` разбирает заголовок в исходном буфере; ответы принимаются с запасом под SOCKS-заголовок, который записывается перед полезной нагрузкой. Переиспользуются `DatagramPacket`. Кэш доменов ограничен 128 записями/60 секундами. Некорректные/фрагментированные пакеты отбрасываются; ошибка разрешения имени/отправки одного пакета не закрывает всё соединение. UDP-источник закрепляется за первым корректным отправителем.
4. **Ресурсы посредника.** По умолчанию до 256 сессий данных, из них до 64 UDP; отдельные 16 мест для рукопожатий. Проверка SOCKS greeting отвечает даже при заполнении мест данных, чтобы нагрузка не вызывала ложный перезапуск. Ожидание данных рукопожатия — 10 секунд; бездействие UDP — 60 секунд, активность учитывается в обоих направлениях. Закрытие UDP закрывает и управляющий TCP, освобождая потоки/сокеты/места. TCP сохраняет half-close и не получает произвольного таймаута простоя. При невозможности получить PID новый процесс уничтожается.
5. **Проверка состояния.** Раз в минуту проверяются и правила, и процессы для обоих VPN-режимов и Proxy. Наличие PID дополнено SOCKS greeting. Результат попытки вывести процесс из группы заморозки/OOM-защиты проверяется; отсутствие подтверждения записывается в журнал, не объявляется успехом.
6. **Диагностика.** Кнопка «Проверить раздачу» показывает состояние, MTU VPN и счётчики внутреннего посредника. Статистика `socks.stats` обновляется атомарно раз в 30 секунд. При запуске посредника есть небольшой UDP DNS-запрос к 1.1.1.1 для диагностики; его неудача не запускает перестроение и не доказывает отсутствие любого UDP. Больших загрузок для теста скорости нет.
7. **Wi-Fi.** В статус добавлена фактическая ширина канала из `SoftApInfo` с декодированием enum (не сырое число). Незнакомые значения ширины не отображаются как МГц. Текст «Ускорения» больше не обещает одинаковую скорость со всеми VPN, предлагает сравнить режимы с WireGuard.
8. **Конфигурация HEV.** Учётные данные экранируются как YAML-строки. Файл передаётся через Base64 как данные, с правами 0600, вместо подстановки пароля внутрь shell heredoc. Перенос строки/`EOF`/символы shell в импортированном пароле не превращаются в root-команды.

Основные файлы: `TetherRoute.kt`, новые `TetherScripts.kt`, `TetherLease.kt`, `SocksUdp.kt`, `LocalSocks.kt`, `TetherWatch.kt`, `HotspotConfig.kt`, `HotspotActivity.kt`, layout/strings точки доступа, версия в `app/build.gradle.kts`.

## IPv6 и TTL, выполненные до 3.14

- В 3.13.1 IPv6 перенесён с глобального отключения на FORWARD-правила `NMS_TETHER6` для активных downstream-интерфейсов Wi-Fi/USB/Bluetooth в обоих направлениях. INPUT/OUTPUT и sysctl телефона не выключаются.
- `Prefs.disableTetherIpv6` читает старое `disable_ipv6` для миграции; экспорт использует `disableTetherIpv6`, импорт понимает старое `disableIpv6`.
- `NetworkTweaks` восстанавливает сохранённое глобальное состояние 3.13. При другом boot id старые sysctl не записываются в новые интерфейсы. `restoreLegacyIpv6` остаётся только для этого восстановления.
- TTL применяется только к прямой IPv4-раздаче с Wi-Fi AP на мобильный upstream, в mangle/FORWARD. «Авто» берёт TTL телефона. При VPN/Proxy показывается пауза. Это не универсальное доказательство обхода ограничений оператора.
- Для работы TTL/IPv6-фильтра отключается hardware/BPF offload с сохранением прежних настроек. Это может стоить скорости и энергии; не включать его обратно без проверки, что трафик не обходит правила.

## Проверки и воспроизведение

В `store/qa-3.14/` сохранены результаты. Для обеих сборок проходят **30 тестов**, ошибок/падений нет: shell-команды на поддельных firewall/procfs; сохранение/принятие маршрута; реальные loopback TCP/UDP; ширина Wi-Fi. Проверены 16 МиБ TCP с SHA-256 и half-close, 16 параллельных TCP, UDP 0/32/1200/16000/60000 байт, отказ второго UDP при лимите, 20 циклов закрытия/повторного открытия, простои и заполненный посредник.

На одноразовом Android API 37 arm64-эмуляторе:

- реальными iptables/ip rule проверены обычный VPN и Proxy, отсутствие DNS-правила и более раннее ACCEPT, сохранение временных защитных правил при teardown;
- INPUT/OUTPUT и настройки IPv6 телефона до/после совпали;
- нативный bundled HEV разобрал новый YAML со спецсимволами/переносами в пароле и создал тестовый TUN; безопасная передача файла через Android shell проверена;
- настоящий `LocalSocks.start()` запустил отдельный `app_process` с UID приложения, клиент внутри Android проверил 8 МиБ TCP + half-close и UDP 1200 байт до локального сервера на Mac;
- отдельный процесс записал живые TCP/UDP-счётчики; экран точки доступа содержит новую кнопку/IPv6-настройку и не падает.

Команды из корня проекта:

```sh
./gradlew --offline :app:testModernDebugUnitTest :app:testA10DebugUnitTest
./gradlew --offline :app:assembleModernRelease :app:assembleA10Release
python3 tools/check-tethering-emulator.py --serial emulator-5580 --native-hev --output /tmp/nms-route-qa
```

Для Gradle на этом Mac использовался `JAVA_HOME='/Applications/Android Studio.app/Contents/jbr/Contents/Home'`. Скрипт эмулятора экспортирует shell из реально скомпилированного `TetherScripts`, требует `assembleModernDebug`, свободных NMS-правил и userdebug-root. Он меняет только временные интерфейсы/правила в указанном одноразовом эмуляторе и отказывается работать на физическом устройстве.

Debug-инструменты: `SocksLab` с `--ez process true` запускает настоящий отдельный процесс на активной сети; `SocksProbeCli tcp|udp <relayPort> <user> <pass> <IPv4 цели> <порт цели>` запускает клиент внутри Android. Они исключены из release. Не записывать реальные учётные данные пользователя в отчёты. Для TCP half-close нельзя использовать ADB forward как прозрачный транспорт: он изменяет закрытие потока. Для UDP не использовать `adb exec-out` + netcat как доказательство доставки stdin; финальная проверка делалась Android-клиентом.

В одном раннем JVM-прогоне был UDP-таймаут при повторном открытии сессии; добавлены сообщения состояния и расширен тест до 20 циклов, последующие полные прогоны обеих сборок прошли. Продолжать наблюдать при нагрузочных испытаниях на телефоне; не представлять единичную успешную проверку как измерение производительности.

## Ограничения и оставшиеся задачи

1. **Скорость через SIM/WireGuard не измерена.** Физического телефона по ADB нет. Проверки Android используют его активную обычную виртуальную сеть, не настоящий WireGuard и не мобильный модем. Нет утверждения о проценте ускорения, экономии батареи или работе в фоне на OxygenOS.
2. Сравнить телефон и Mac на одном сервере: обычный VPN / «Ускорение» / выбранный SOCKS5, загрузка/отдача, задержка под нагрузкой, потери, температура, экран выключен и простой. Ограничить объём мобильных данных. Автовыбор по результатам пока не сделан; ручной выбор сохранён.
3. Не менять MTU/глобальные TCP-буферы вслепую. Clamp MSS уже есть в обычном VPN; 8500 — MTU виртуального HEV, не размер внешнего пакета WireGuard. Новая диагностика только показывает MTU.
4. VPN/Proxy-маршрутизация пока для Wi-Fi AP. USB/Bluetooth в этой работе получили лишь IPv6-фильтр. Для USB VPN/Proxy нужен отдельный перенос маршрутизации на несколько downstreams.
5. Kernel-backend WireGuard (`wg-quick`) может не представляться как Android VPN Network. Отдельное обнаружение/маршрутизация через него пока не реализованы. «Ускорение» требует, чтобы NetModeSwitch входил в VPN при списках приложений.
6. Cached thread pool остался блокирующим, но ограничен количеством сессий/рукопожатий. Неблокирующий/нативный SOCKS — отдельный кандидат на benchmark с сохранением Android Network binding, не механическая замена пула на фиксированный (есть риск взаимного ожидания направлений).
7. Защита от заморозки зависит от cgroup/SELinux/OEM. На cgroup v1 отсутствие подтверждения не равно доказанному зависанию. Нужен отдельный замер с выключенным экраном на телефоне.
8. Нативный HEV: единственный bundled ABI `arm64-v8a`, проверена версия `2.18.0 d9dca26`. Полноценного ICMP-интернета через HEV по умолчанию нет; ping не использовать как проверку скорости/внешней связности.
9. Совместная работа с AdGuard на физическом телефоне не проверялась. После глобального отключения из 3.13 может понадобиться перезапустить AdGuard/VPN и переподключить сеть после восстановления флагов.
10. Общий `Root.exec()` по-прежнему возвращает stdout/stderr без проверки exit code; критические команды маршрута теперь имеют собственные проверяемые маркеры. Не считать любую строку вывода успехом.
11. Full Lint ранее находил старые ошибки проекта (Modern 18, A10 49); они не исправлялись массово. Release-сборка с lintVital проходит. Runtime Android 10 отдельно не проверялся, A10 собран и протестирован на JVM.

Не включать в коммит весь старый dirty tree. APK в `store/` — готовые артефакты для ручной установки пользователем; обновление/публикация во внешний сервис не выполнялись.
