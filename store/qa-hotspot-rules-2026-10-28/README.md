# Условие «Точка доступа» — 28.10.2026

В редакторе правила: **Когда → Точка доступа → Способ раздачи**. Варианты: «Любой способ», «Через VPN», «Через прокси», «Напрямую».

Условие действует при активной раздаче по Wi-Fi и совпадении выбранного в NetModeSwitch режима. Само подключение VPN на телефоне не означает VPN-раздачу. Наличие интернета у клиента не проверяется. USB, Bluetooth и локальная точка без раздачи не подходят.

`ConditionWatch` получает системный sticky broadcast `TETHER_STATE_CHANGED` и читает `tetherArray`. Это позволяет восстановить состояние при запуске процесса без периодического опроса и root-команд. Изменение `Prefs.tetherMode` пересчитывает условие, даже если точка не перезапускается. При неизвестном снимке состояние правила сохраняется. Режим условия хранится отдельно от режимов действий в JSON-поле `tApVia`; отсутствие поля совместимо со старыми правилами.

В начале такого правила скрыты действия, которые могут выключить его собственное условие: переключение Wi-Fi/точки, режим полёта и переподключение мобильной сети. В блоке окончания можно управлять Wi-Fi и точкой, как у других правил соединений. Добавлены подписи и значки для списка, виджетов и плиток.

## Проверки

- 127 unit-тестов ModernDebug и 127 A10Debug, без ошибок. Шесть новых тестов покрывают отсутствие данных, выключенную точку, интерфейсы Wi-Fi/USB/BT, все сочетания режимов и переходы между ними, подписи и независимость режима условия от действий.
- Обе release-сборки, R8 и lintVital завершились успешно. Окончательные сборки выполнены с отдельным `layout.buildDirectory` в `/tmp/nms-hotspot-rules-build`, без build cache: параллельные сборки в общем `app/build` конфликтовали. Debug-сборки также проверены.
- На одноразовой read-only копии Android 10: реальные системные запуск/остановка раздачи; переключение предпочтения DIRECT → VPN → PROXY → DIRECT без перезапуска точки; повторная установка того же режима; повторный запуск точки; восстановление sticky-состояния после force-stop процесса и выключение после восстановления. Снимки `*.json` фиксируют результат настоящего метода `ConditionWatch.holds` через debug-only `HotspotRuleLab`.
- На том же Android 10: выбор всех вариантов, сохранение и чтение из JSON, светлая тема 360dp/100%, тёмная 360dp/150%, меню режимов. Полные JSON roundtrip для четырёх вариантов, совместимость с отсутствующим и неизвестным `tApVia` проверены настоящим Android `JSONObject`.
- Сертификат обоих APK совпадает с прежним: SHA-256 `40ed2e2df70aec2d7072ff3d3437364de80928691b6d632a95f008c9b98308f2`. Package `com.netmode.switcher`, versionCode 85, minSdk 34/29. Контрольные суммы APK и результаты unit-тестов — в `checks.json`.

Эмулятор не предоставлял root/Shizuku самому приложению. Проверены обнаружение и сопоставление условий; выполнение и возврат привилегированных действий правила, настоящий выход клиента через VPN/прокси и физический телефон не проверялись. При проверке режимов fixture меняет только предпочтение, а не сетевые правила. Для запуска системной точки использовался `HotspotCli` через отладочный root эмулятора. Обычный Wi-Fi в Android 10 пришлось отключить, чтобы освободить общий интерфейс `wlan0`.

`HotspotRuleLab` доступен только в debug. Пример чтения: `am start -W -f 0x10008000 -n com.netmode.switcher/.HotspotRuleLab --es op snapshot`. Другие операции: `seed`, `route`, `edit`; у route/edit режим задаётся, например, `--es mode VPN`. CLEAR_TASK нужен, чтобы Android не отправлял команду редактору из прежнего тестового запуска. Fixture перезаписывает тестовые правила, поэтому предназначен только для одноразового эмулятора.
