# Правила: нажатия плиток и диапазоны раздачи — 28.10.2026

Добавлено:

- «Когда → Нажатие плитки приложения»: выбор стабильного компонента из списка TileService, включая собственные плитки приложения, кроме плиток самих правил. Каждое нажатие — отдельное событие без неявного обратного действия. Дополнительные условия и уведомление/запрос перед запуском сохраняются.
- Общая служба AppWatchService принимает клики SystemUI. Для меняющихся подписей есть обучение по следующему нажатию. Подстроки не сопоставляются; неоднозначные подписи не запускают случайное правило.
- На Android, скрывающем accessibility-клики, используется штатный буфер QSLog с точным компонентом. Он читается через root/Shizuku раз в 2 секунды только при открытой шторке. Закрытие шторки останавливает чтение. История до включения наблюдения, повторы снимков, старые события и длинные/вторичные нажатия отбрасываются. Программные клики Tiles.set подавляются, чтобы не запустить цикл правил.
- «Когда → Точка доступа»: способ раздачи и фактический диапазон (любой / 2,4 / 5 ГГц). Неизвестная частота не угадывается по сохранённой конфигурации. Диапазон читается по системным событиям с ограниченными повторными попытками при запуске AP; постоянного root-опроса диапазона нет.
- «Что сделать → Точка доступа» и пользовательские окончания, включая разблокировку: способ раздачи плюс текущий / 2,4 / 5 ГГц. Для смены диапазона используется общий проверенный запуск пресетов с mutex, проверкой перед остановкой и подтверждением записи. Неудача не запускает AP в другом диапазоне. Для Android 10 сохранён выбор диапазона в системных настройках; автоматический выбор требует root и Android 11+.
- При автоматическом возврате сохраняется полная прежняя карта диапазонов/каналов без паролей. Ошибка возврата оставляет запись для повторной попытки. Новые JSON-поля совместимы с отсутствующими/неизвестными значениями старых правил. Прежние правила без диапазона работают как раньше.

Проверено:

- 137 ModernDebug + 137 A10Debug unit-тестов, 0 failures/errors. Новые тесты покрывают диапазон+маршрут, неизвестное радио, двухдиапазонный AP, подписи и окончания, конфликты, порядок сохранения прежнего состояния, точный возврат канала, отказ записи, сопоставление подписи и дедупликацию QSLog.
- Обе release-сборки, R8 и lintVital; изолированные buildDirectory и project cache в /tmp. Версия 3.30 / 85 сохранена.
- Одноразовая read-only копия NMS_Test, emulator-5582 / API 37: реальные нажатия тестовой TileService и их записи с точным компонентом в QSLog; доступность определения открытой шторки из обычной службы; Android JSONObject roundtrip всех комбинаций диапазона/маршрута, обоих окончаний и нового триггера; редакторы в светлой и тёмной теме с 150% шрифтом. После визуальной проверки маршрут и диапазон вынесены под заголовок действия, чтобы крупный шрифт не сжимал его до одного символа.

Ограничения проверки: первоначальные UI-прогоны не подтвердили обычные accessibility-клики Android 17, поэтому добавлен QSLog. Установленный в эмулятор официальный Shizuku не выдал тестовому приложению разрешение сервера; полный автоматический путь QSLog → привилегированное действие правила не подтверждён. Реальные переключение диапазона/возврат на физическом телефоне, выход клиентов через VPN/прокси и OEM-шторка не проверялись. Поддержка нажатий зависит от доступности accessibility-события или буфера QSLog прошивки. Автоматическая смена рабочей частоты внутри уже запущенного AP без системного события отдельно не отслеживается.
