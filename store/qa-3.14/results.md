# Проверки NetModeSwitch 3.14

Завершены 22.10.2026. Физический телефон не использовался. Это проверки корректности и устойчивости, не замер скорости мобильной сети/VPN.

| Проверка | Результат |
| --- | --- |
| Modern debug JVM | 30 тестов, 0 ошибок/падений |
| A10 debug JVM | 30 тестов, 0 ошибок/падений |
| Подписанные Modern/A10 release APK, R8 и lintVital | Сборка успешна |
| Android API 37: реальные iptables, policy rules, VPN NAT/MSS, DNS, guard | Пройдено |
| Отсутствующее DNS-правило / ACCEPT перед защитой | Ошибка обнаруживается |
| Защитные IPv4/IPv6-правила во время teardown | Сохраняются |
| Новая запись конфигурации и native HEV | Спецсимволы сохраняются как данные; HEV разбирает YAML и создаёт тестовый TUN |
| IPv6 sysctl, INPUT/OUTPUT телефона | До/после совпадают |
| Настоящий отдельный app_process внутри Android | 8 МиБ TCP, SHA-256 и half-close; UDP 1200 байт — пройдено |
| Файл счётчиков отдельного процесса | TCP отправлено 8388608 байт, принято 32; UDP 1200/1200; ошибок 0 |
| Экран точки доступа | Новая кнопка и подпись IPv6 видны; падений нет |

JVM включает передачу TCP 16 МиБ, 16 параллельных TCP, UDP 0/32/1200/16000/60000 байт, 20 циклов закрытия/повторного открытия UDP, лимиты/простои, ответ на greeting при заполненном посреднике, сохранение маршрута между экземплярами контроллера, проверку безопасной записи пароля и декодирования ширины Wi-Fi.

Свидетельства: `junit/` (XML), `route-results.txt`, `android-process-results.txt`, `android-process-stats.txt`, `hotspot.png`, `build-info.json`. В XML названия Debug-вариантов; они не являются тестами физического Android 10.

Воспроизведение:

```sh
./gradlew --offline :app:testModernDebugUnitTest :app:testA10DebugUnitTest
./gradlew --offline :app:assembleModernDebug :app:assembleModernRelease :app:assembleA10Release
python3 tools/check-tethering-emulator.py --serial emulator-5580 --native-hev --output /tmp/nms-route-qa
```

Эмулятор должен быть отдельным, пустым userdebug/arm64 с root для shell. Новая проверка в интерфейсе требует app root; в тестовом эмуляторе доступ приложения к root не выдавался, проверено отображение кнопки, а не нажатие root-диагностики. Команды настройки выполнялись через root shell. Проверка отдельного SOCKS использовала активную обычную сеть эмулятора; настоящий WireGuard, оператор и AdGuard не участвовали.

Во время разработки один локальный прогон завершился UDP-таймаутом. После добавления диагностики и расширения проверки до 20 циклов полный набор обеих сборок прошёл. Для нагрузочного испытания на телефоне это остаётся наблюдаемым риском, а не доказанным приростом скорости.
